# M0-3 ｜ 代码排查 —— 问题报告

## 一、概述

`sensor_analyzer.py` 是上一届留下的脚本，**原本意图**是：

1. 读取 `sensor_data.csv`（列：`time`、`value`）
2. 计算 value 的平均值、标准差
3. 剔除离群值（`|value - mean| > 2 * std`）
4. 把清洗后的数据保存为 `cleaned_data.csv`（`time,value` 两列）
5. 打印统计摘要

但原脚本既有跑不通的地方，也有"能跑但结果不对"的地方。本文件逐条记录
**发现过程、现象、原因和修复方式**。

修复后对给定示例数据的运行结果：

```
=== 传感器数据分析 ===
共读取 60 条数据
均值 mean = 50.4315
标准差 std = 18.5033
清洗后剩余 57 条
已保存到 cleaned_data.csv
```

## 二、如何运行

```bash
# 方式一：显式指定输入输出
python3 sensor_analyzer.py --input sensor_data.csv --output cleaned_data.csv

# 方式二：无参数，默认读写当前工作目录下的 sensor_data.csv / cleaned_data.csv
python3 sensor_analyzer.py
```

两种方式都支持——因为 `--input` / `--output` 用的是 `default=` 而不是 `required=True`，
不传参数时会自动采用默认文件名。

| 参数 | 默认值 | 说明 |
| :-- | :-- | :-- |
| `--input` | `sensor_data.csv` | 输入 csv 的路径 |
| `--output` | `cleaned_data.csv` | 输出 csv 的路径 |

统计摘要打印到 **stdout**，其中包含 `均值 mean = <数值>` 和 `标准差 std = <数值>` 两行；
错误信息打印到 **stderr**。

## 三、缺陷清单

> 下表中的行号以**原始脚本**为准（即本仓库首次提交 `chore: 初始化 M0-3 工作区` 中的版本）。

| # | 位置 | 现象 | 原因 | 修复方式 |
| :-- | :-- | :-- | :-- | :-- |
| 1 | L37 `row["Value"]` | `KeyError: 'Value'`，程序在**读取阶段**就崩 | csv 表头是小写的 `value`，而代码里写的是 `Value`。`DictReader` 拿表头当字典的键，键名对不上就查不到 | 改为 `row["value"]` |
| 2 | L61 `os.path.join("/", OUTPUT_DIR, OUTPUT_FILE)` | `FileNotFoundError: '/out/cleaned_data.csv'` | 第一个参数 `"/"` 是**系统根目录**，拼出来的绝对路径指向 `/out/`，而这个目录并不存在。`open()` 只会创建文件、**不会创建目录** | 改为 `output_path = OUTPUT_FILE`，即写到当前工作目录 |
| 3 | L52 `acc += (v - mean)` | 算出的 `std` 趋近 0（格式化后显示 `-0.0000`） | 标准差的定义是"偏差**平方和**的平均再开方"。这里直接把偏差相加，正负互相抵消，结果自然接近 0 | 改为 `acc += (v - mean) * (v - mean)` |
| 4 | L53 `std = acc / len(data)` | 得到的是**方差**，不是标准差 | `Σ(v-mean)² / n` 只是方差，标准差还要再开平方根 | 改为 `std = math.sqrt(acc / len(data))`，并 `import math` |
| 5 | L57 `if v > mean + 2 * std` | 只剔除了**偏大**的离群值，偏小的被保留了 | 题目要求按"绝对值超过 2 倍标准差"判定（双侧）。原代码只判断了 `v > mean + 2*std` 这一侧 | 改为 `abs(v - mean) > 2 * std` |
| 6 | L56-58 `for v in data: data.remove(v)` | 按定义应剔除 3 条，实际只剔除了 2 条 | **遍历列表的同时修改列表**：`remove` 之后剩余元素前移，迭代器的内部下标会跳过紧邻的下一个元素 | 不再原地删除，改成"挑出要保留的" |
| 7 | L58 `data.remove(v)` | 剔除后 `data` 剩 58 条、`times` 仍是 60 条，**时间和数值错位** | `remove` 只从 `data` 里删，没有同步删 `times`。而输出需要 time/value 成对出现，错位后两者对不上 | 改用 `zip(times, data)` 配对遍历，成对处理 |
| 8 | L28 定义 `cleaned = []`，L65 使用 | 打印"清洗后剩余 0 条"，`cleaned_data.csv` 里只有表头 | 整个脚本**没有任何地方往 `cleaned` 里 append 过东西**，它永远是空列表 | 在"挑出保留的"循环里 `cleaned.append((t, v))` |
| 9 | L66 `writer.writerow([v])` | 表头写了 `time,value` 两列，数据行却只有一格，内容是 `"(0.1, 43.2612)"` 这样的字符串 | `writerow` 接收一个列表，**列表里每个元素对应 csv 里的一格**。只传一个元素（还是个元组）就只写一格 | 改为 `writer.writerow([t, v])` |
| 10 | L33 / L37 / L47 / L52 附近 | 文件不存在、空文件、列名不符、非数值内容——四种输入全部抛出 **Traceback** | 脚本对输入没有任何校验，异常一路抛到最外层 | 增加四道检查 + `die()` 函数统一"打印可读提示并以非 0 退出码结束" |
| 11 | L22-23 写死的 `INPUT_FILE` / `OUTPUT_FILE` | `--input` / `--output` **完全被无视** | 脚本从不读取命令行参数，文件名写死在常量里 | 引入 `argparse`，使用 `default=` 同时支持"无参数"与"显式指定"两种调用方式 |

> 题目提示"缺陷数量：8 处"。按不同粒度划分会得到不同条数——例如 #3 与 #4 是**同一个公式**上的两处问题，
#5 / #6 / #7 / #8 则**共享同一个根因**（详见下一节）。上表按"一个症状一条"整理。

## 四、缺陷之间的依赖关系

这道题的难点在于：**前面的缺陷不修，后面的现象会被掩盖**。实测中确实如此：

```
#1 列名错误不修
   → 程序在读取阶段就崩，后面的均值、标准差、清洗、输出全都走不到
   → #2 ~ #9 的问题根本看不见

#3 / #4 标准差公式不修
   → std 趋近 0
   → #5 的判定条件 mean + 2*std 约等于 mean
   → "所有大于均值的数"都被判成离群值，剔除条件完全失效

#5 / #6 / #7 / #8 是同一个根因
   → 都源自"从 data 里原地删除不需要的元素"这个做法
   → 一旦改成"遍历配对、挑出要保留的"，四个问题一次解决：
      · 不再边遍历边删（#6）
      · times 与 data 不会错位（#7）
      · cleaned 有了内容（#8）
      · 判定条件变成"保留 |v-mean| <= 2*std"，天然是双侧（#5）
```

## 五、边界情况处理

题目要求"不允许裸崩（Traceback）"。目前的实现：

| 输入情况 | 处理方式 | 退出码 |
| :-- | :-- | :--: |
| 文件不存在 | 读取前用 `os.path.exists()` 检查，打印「错误：找不到文件「xxx」」 | 1 |
| 空文件（只有表头，没有数据行） | 读取结束后检查 `data` 是否为空，打印「错误：文件里没有任何数据行」 | 1 |
| 列名不符（缺少 `time` 或 `value`） | 读表头后用 `reader.fieldnames` 校验，并打印实际列名 | 1 |
| 非数值内容 | 用 `try/except ValueError` 包住 `float()` 转换，打印出错的那一行 | 1 |

四类错误统一通过 `die()` 函数处理：

```python
def die(message):
    """打印错误信息，并以非 0 退出码结束程序。"""
    print(message, file=sys.stderr)
    sys.exit(1)
```

错误信息走 **stderr**（不是 stdout），这样别人重定向 stdout 抓结果时不会混入错误信息。

**实测记录：**

| 输入 | 输出 | 退出码 |
| :-- | :-- | :--: |
| 正常数据（60 条） | `清洗后剩余 57 条` | 0 |
| 文件不存在 | `错误：找不到文件「sensor_data.csv」` | 1 |
| 空文件 | `错误：文件里没有任何数据行` | 1 |
| 列名不符（`t,v`） | `错误：csv 需要 time 和 value 两列，实际列名是 ['t', 'v']` | 1 |
| 非数值（`1,abc`） | `错误：这行数据不是数字：{'time': '1', 'value': 'abc'}` | 1 |

## 六、已知遗留问题

读取和写入 csv 时用的是 `open(...)` 而没有用 `with open(...) as f:`，
因此**文件句柄不会自动关闭**。脚本很短、进程结束时操作系统会回收，
实际影响很小，但严格来说是个资源管理瑕疵。正确写法：

```python
with open(args.input, "r") as f:
    reader = csv.DictReader(f)
    ...
```
